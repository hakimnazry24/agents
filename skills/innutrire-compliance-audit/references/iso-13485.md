# ISO 13485:2016 — Quality management system (key QM)

**In plain words:** the organisation's rulebook: written procedures and records that show the product is designed, built, released and supported under control. It holds the evidence from all the other standards.

**Relation to INNUTRIRE:** many engineering practices already exist (git, reviews, automated tests, release pipelines, Trello). The gap is usually writing them down as procedures and keeping records.

---

### QM-01 Documented procedures
- **Applies to:** all
- **Clause:** 4.2
- **Look for:** written procedures for development, review, release, deployment and incident handling (`docs/`, `CONTRIBUTING*`, `AGENTS.md`, `CLAUDE.md`, runbooks).
- **Met:** formal procedures. **Partial:** informal guidance. **Gap:** none.
- **Severity if not met:** Medium

### QM-02 Document control
- **Applies to:** all
- **Clause:** 4.2.4
- **Look for:** documents kept in version control with history and an owner or approver.
- **Met:** versioned and reviewed through pull requests. **Partial:** versioned only. **Gap:** none.
- **Severity if not met:** Low

### QM-03 Records are kept
- **Applies to:** all
- **Clause:** 4.2.5
- **Look for:** durable records of tests, reviews and releases: CI run history, release notes, pull-request reviews, deployment logs with retention.
- **Met:** records with retention. **Partial:** records exist but retention is unclear. **Gap:** none.
- **Severity if not met:** Low

### QM-04 Design and development planning and inputs
- **Applies to:** backend, tablet-app, monitoring
- **Clause:** 7.3.2, 7.3.3
- **Look for:** a design plan and design inputs (requirements); see SW-02 and SW-03.
- **Met:** both. **Partial:** one. **Gap:** neither.
- **Severity if not met:** Medium

### QM-05 Design review, verification and validation
- **Applies to:** backend, tablet-app, monitoring
- **Clause:** 7.3.5, 7.3.6, 7.3.7
- **Look for:**
  - required reviews: branch protection or a reviewer rule in the docs;
  - verification: tests (see SW-05 and SW-06);
  - validation with real users or clinical data: usability tests, the field study.
- **Met:** all three. **Partial:** some. **Gap:** none.
- **Severity if not met:** Medium

### QM-06 Control of design changes
- **Applies to:** all
- **Clause:** 7.3.9
- **Look for:** every change described, reviewed and approved before release: pull-request template, PR-title rules, conventional commits, changelog, a promote workflow with approval.
- **Met:** all of these. **Partial:** some. **Gap:** direct pushes to main.
- **Severity if not met:** Medium

### QM-07 Validation of software tools used in the QMS
- **Applies to:** all
- **Clause:** 4.1.6
- **Look for:** a record of the tools used to build, test and deploy (CI, Ansible, PyInstaller, AI coding tools) and the reason each is fit for use.
- **Met:** a tool list with rationale. **Partial:** a tool list only. **Gap:** none.
- **Severity if not met:** Low

### QM-08 Supplier control for third-party software and services
- **Applies to:** all
- **Clause:** 7.4
- **Look for:** an assessment of key suppliers (cloud host, Tailscale, GitHub, major libraries); ties to SW-09.
- **Met:** documented. **Partial:** listed only. **Gap:** none.
- **Severity if not met:** Low

### QM-09 Feedback, complaints and corrective action
- **Applies to:** all
- **Clause:** 8.2.1, 8.2.2, 8.5.2
- **Look for:** a route for hospital feedback and complaints, and bug fixes traced back to their root cause (bug tickets with a root-cause note, regression tests).
- **Met:** a documented loop. **Partial:** bug tracking only. **Outside repo** for the Trello process.
- **Severity if not met:** Medium

### QM-10 Medical device file
- **Applies to:** all
- **Clause:** 4.2.3
- **Look for:** one index pointing to all the evidence: intended use, risk file, requirements, tests, usability, labelling and instructions for use, release records.
- **Met:** exists. **Gap:** none.
- **Severity if not met:** Medium
