# IEC 62366-1:2015+A1:2020 — Usability engineering (key UE)

**In plain words:** make sure busy staff can use the system without making dangerous mistakes, by designing the screens around real users and testing them with those users.

**Relation to INNUTRIRE:** the REE form, the score calculators, unit entry (kg, cm, mL, °C) and reading the result are all safety-related parts of the user interface.

---

### UE-01 Use specification
- **Applies to:** tablet-app, monitoring
- **Clause:** 5.1
- **Look for:** who the users are (ICU nurses, dietitians), the environment (ICU bedside, gloves, interruptions), the patient population and the main tasks.
- **Met:** written. **Partial:** implied in the README. **Gap:** none.
- **Severity if not met:** Medium

### UE-02 Safety-related user interface parts identified
- **Applies to:** tablet-app
- **Clause:** 5.2, 5.3
- **Look for:** a list of the screens and fields where a mistake could harm a patient, and known use errors such as past bugs (BMI labels, decimal severity scores, trauma level).
- **Met:** listed. **Gap:** none.
- **Severity if not met:** High

### UE-03 Units always shown and unambiguous
- **Applies to:** tablet-app, monitoring
- **Clause:** 5.6 (user interface specification)
- **Look for:** in `app/components/keyboards`, `app/components/score_forms`, `app/features/ree_calculation`, `add_new_patient` and `edit_patient`: is a unit label shown next to every numeric input and result? Are kcal and kcal/kg clearly separated?
- **Met:** every numeric field has a unit. **Partial:** some don't. **Gap:** units are often missing.
- **Severity if not met:** High

### UE-04 Input limits and validation messages
- **Applies to:** tablet-app
- **Clause:** 5.6
- **Look for:** minimum and maximum values on numeric inputs, decimal rules, blocking or warning on out-of-range values, and clear messages.
- **Met:** all clinical inputs bounded with messages. **Partial:** some. **Gap:** free numeric entry.
- **Severity if not met:** High

### UE-05 Confirmation before saving clinically important results
- **Applies to:** tablet-app
- **Clause:** 5.6
- **Look for:** a review or summary step before a prediction is saved or a patient record is changed or deleted, and undo or soft delete.
- **Met:** a review step and soft delete. **Partial:** one of the two. **Gap:** neither.
- **Severity if not met:** Medium

### UE-06 Results are clear and hard to misread
- **Applies to:** tablet-app, monitoring
- **Clause:** 5.6
- **Look for:** clear labelling of the REE result and the energy recommendation (they differ by the injury factor), sensible rounding, and AI explanations labelled as supporting information.
- **Met:** clear. **Partial:** some ambiguity. **Gap:** values shown without labels or units.
- **Severity if not met:** High

### UE-07 Usability evaluation plan and results
- **Applies to:** tablet-app
- **Clause:** 5.7, 5.8, 5.9
- **Look for:** records of formative tests (early tests with a few nurses) and a summative test plan or report, in `docs/` or linked.
- **Met:** both. **Partial:** formative only. **Outside repo** if a link points elsewhere. **Gap:** none.
- **Severity if not met:** Medium

### UE-08 Usability engineering file
- **Applies to:** tablet-app
- **Clause:** 4.2
- **Look for:** one place collecting UE-01 to UE-07 records.
- **Met:** exists. **Gap:** none.
- **Severity if not met:** Low
